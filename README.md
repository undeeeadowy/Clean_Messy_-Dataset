# 🧹 Sales Data Cleaning Pipeline

Полный pipeline очистки сырых данных продаж — от "грязного" CSV до чистого датасета, готового для аналитики и отчётности.

## Задача

Исходный датасет продаж содержал множество типичных проблем реальных данных:
- Дубликаты написания товаров, регионов и сегментов
- Два разных формата дат в одной колонке
- Пропущенные значения в 6 колонках
- Несоответствия в расчётных полях
- Выбросы в числовых данных
- Дублирующиеся записи и коллизии в ID

## Шаги очистки

1. **Профайлинг** — структура, типы данных, пропуски, распределения
2. **Стандартизация текста** — унификация ProductName, Region, CustomerSegment, ProductCategory через mapping словари
3. **Исправление типов** — OrderDate из object в datetime64, обработка 3 форматов дат
4. **Обработка пропусков** — восстановление через формулу TotalPrice = Quantity × UnitPrice, медиана по товару, заполнение GUEST для гостевых покупок
5. **Дубликаты** — удаление 5 полных дубликатов, перегенерация TransactionID
6. **Выбросы** — capping по IQR методу для Quantity и UnitPrice
7. **Консистентность** — пересчёт TotalPrice по формуле
8. **Экспорт** — сохранение чистого датасета

## Ключевые технические решения

**Два формата дат:**
Исходный датасет содержал даты в форматах `MM/DD/YYYY`, `DD-MM-YYYY` и `YYYY-MM-DD` одновременно. Решение — обработка каждого формата отдельной маской через `pd.to_datetime()` с явным `format=`.

**Выбросы — capping вместо удаления:**
Вместо удаления строк с аномально высокими значениями применён capping (ограничение верхней границей IQR). Это сохраняет все транзакции, включая потенциально реальные крупные заказы.

**Пропуски в числовых полях:**
Приоритет восстановления через формулу `TotalPrice = Quantity × UnitPrice`. Для оставшихся пропусков — медиана в разрезе `ProductName`, не общая медиана.
